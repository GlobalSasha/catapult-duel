Статус: P0-01…P0-12 готовы, P0-13 в работе  
Связанные документы:

## 1. Цель P0

Получить серый, но полностью играбельный локальный матч:

- две катапульты;
- каменный снаряд;
- угол и сила;
- одинаковая воспроизводимая траектория;
- столкновение и урон;
- смена хода;
- победа и новый матч;
- мышь и touch.

Каждая задача ниже должна завершаться работающим и отдельно проверяемым результатом.

## 2. Правила выполнения

- Выполнять задачи строго по порядку.
- Не добавлять функциональность следующей задачи заранее.
- Не добавлять сеть, бота, погоду, защиту или финальные ассеты.
- Не менять числа из GDD без фиксации причины.
- Game Core не должен импортировать Phaser.
- После каждой задачи запускать указанные проверки.
- Если новая задача требует переделки уже готовой архитектуры, сначала остановиться и обновить Technical Design.

## 4. Детализация задач

### P0-01. Каркас проекта

**Сделать**

- Создать Vite-проект без React/Vue.
- Подключить TypeScript strict.
- Установить Phaser 4.1.0. Версия 4.2.1 временно не используется из-за отсутствующего `phaser.d.ts` в npm-пакете.
- Подключить Vitest.
- Зафиксировать минимальную версию Node.js 22.12.
- Добавить npm-команды `dev`, `typecheck`, `test`, `build`, `preview`.
- Добавить минимальные `index.html`, `src/main.ts` и `src/style.css`.

**Не делать**

- Не создавать сервер.
- Не подключать UI-фреймворк.
- Не добавлять ассеты.
- Не создавать игровые механики.

**Готово, когда**

- `npm run dev` открывает пустую страницу без ошибок;
- `npm run typecheck`, `npm run test` и `npm run build` завершаются успешно;
- версии зависимостей зафиксированы lock-файлом.

### P0-02. Адаптивная BattleScene

**Сделать**

- Создать `BootScene` и `BattleScene`.
- Настроить логический мир 1600 × 900.
- Добавить однотонный фон и подпись `Battle P0`.
- Настроить сохранение пропорций и центрирование canvas.
- Показать предложение повернуть телефон в портретной ориентации.

**Не делать**

- Не добавлять физику.
- Не добавлять управление выстрелом.
- Не создавать главное меню.

**Готово, когда**

- сцена видна на широком и узком экране;
- изменение размера окна не ломает canvas;
- элементы не выходят за логический мир.

### P0-03. Конфигурация и типы

**Сделать**

- Создать `GAME_CONFIG`.
- Описать `PlayerId`, `BattlePhase`, `PlayerState`, `BattleState`.
- Создать функцию `createInitialBattleState()`.
- Зафиксировать позиции катапульт, здоровье и активного игрока.

**Не делать**

- Не импортировать Phaser в `game/core`.
- Не добавлять погоду или специальные снаряды.

**Готово, когда**

- все числа берутся из конфигурации;
- новый вызов создаёт независимое чистое состояние;
- TypeScript не допускает неизвестную фазу или игрока.

### P0-04. Чистая симуляция выстрела

**Сделать**

- Реализовать перевод угла и силы в начальную скорость.
- Реализовать 120 фиксированных шагов в секунду.
- Добавить гравитацию.
- Добавить зеркальное направление правого игрока.
- Возвращать `ShotResult` с точками 30 раз в секунду.
- Завершать полёт за границей мира или через 10 секунд.

**Не делать**

- Не обращаться к canvas, сцене или времени браузера.
- Не добавлять столкновения и урон.
- Не использовать `Math.random()`.

**Готово, когда**

- одинаковый вход всегда возвращает одинаковые точки;
- правый выстрел зеркален левому;
- симуляция всегда завершается.

### P0-05. Тесты баллистики

**Сделать**

- Проверить минимальную и максимальную силу.
- Проверить углы 10°, 45° и 80°.
- Проверить зеркальность.
- Проверить воспроизводимость.
- Проверить выход за границу и timeout.
- Проверить количество сохранённых точек.

**Не делать**

- Не тестировать визуальные координаты Phaser.
- Не использовать большие snapshot-файлы со всей траекторией.

**Готово, когда**

- тесты ловят изменение гравитации или формулы скорости;
- сравнение float использует допустимую погрешность;
- `npm run test` и `npm run typecheck` проходят.

### P0-06. Арена и катапульты

**Сделать**

- Нарисовать землю простой геометрией.
- Нарисовать две различимые катапульты.
- Отобразить здоровье.
- Визуально выделить активного игрока.
- Связать отображение с `BattleState`.

**Не делать**

- Не добавлять финальные изображения.
- Не анимировать разрушение.
- Не добавлять защиту.

**Готово, когда**

- позиции на сцене соответствуют состоянию;
- левая и правая стороны легко различимы;
- смена тестового состояния обновляет UI.

### P0-07. Прицеливание

**Сделать**

- Добавить угол 10–80°.
- Добавить силу 20–100.
- Добавить кнопку «Огонь».
- Показать текущие числовые значения.
- Показать preview первых 25% траектории.
- Пересчитывать preview только после изменения параметров.

**Не делать**

- Не применять урон.
- Не менять ход.
- Не добавлять жест оттягивания.

**Готово, когда**

- нельзя задать недопустимое значение;
- preview меняется предсказуемо;
- кнопка создаёт одну команду на одно нажатие.

### P0-08. Анимация выстрела

**Сделать**

- Создать визуальный камень.
- Заблокировать управление после выстрела.
- Анимировать камень по точкам `ShotResult`.
- Следовать камерой за снарядом.
- Удалять снаряд после завершения траектории.

**Не делать**

- Не пересчитывать физику в сцене.
- Не разрешать повторный выстрел во время полёта.
- Не добавлять урон.

**Готово, когда**

- снаряд проходит по рассчитанной траектории;
- низкий FPS не меняет конечную точку;
- камера не теряет снаряд;
- после полёта на сцене не остаётся старый объект.

### P0-09. Столкновение и урон

**Сделать**

- Добавить круглый collider снаряда.
- Добавить прямоугольники земли и катапульт.
- Остановить симуляцию при первом столкновении.
- Рассчитать урон по скорости попадания.
- Ограничить здоровье диапазоном 0–100.
- Показать число нанесённого урона.

**Не делать**

- Не добавлять отскоки.
- Не добавлять взрывы.
- Не добавлять материалы.

**Готово, когда**

- попадание уменьшает здоровье ровно один раз;
- попадание в землю не наносит урон;
- промах не меняет здоровье;
- автоматические тесты покрывают три случая.

### P0-10. Смена хода

**Сделать**

- Реализовать `BattleController`.
- Добавить фазы `aiming`, `projectile-flight`, `resolving`.
- После разрешения результата менять активного игрока.
- Увеличивать номер хода.
- Переводить камеру к следующей катапульте.

**Не делать**

- Не менять состояние напрямую из сцены.
- Не разрешать ход неактивного игрока.

**Готово, когда**

- игроки могут последовательно сделать минимум десять выстрелов;
- двойное нажатие не создаёт два снаряда;
- неправильная фаза возвращает типизированную ошибку;
- тесты turn flow проходят.

### P0-11. Победа и новый матч

**Сделать**

- Проверять победу после урона.
- Добавить фазу `finished`.
- Создать `ResultScene`.
- Показать победителя и число ходов.
- Добавить кнопку «Новый матч».

**Не делать**

- Не сохранять статистику.
- Не добавлять реванш по сети.
- Не создавать главное меню.

**Готово, когда**

- матч завершается при нулевом здоровье;
- после победы нельзя стрелять;
- новый матч имеет 100 здоровья у обоих игроков;
- страница не перезагружается.

### P0-12. Мышь, touch и адаптация

**Сделать**

- Проверить и исправить управление мышью.
- Проверить touch через браузерную эмуляцию.
- Обеспечить активные области не меньше 44 × 44 CSS-пикселей.
- Проверить горизонтальный телефонный viewport.
- Проверить, что UI не перекрывает катапульты.

**Не делать**

- Не полировать финальную графику.
- Не добавлять новые механики.

**Готово, когда**

- полный матч можно пройти только касаниями;
- полный матч можно пройти только мышью;
- поворот и resize не требуют перезагрузки.

### P0-13. Финальная проверка

**Сделать**

- Запустить typecheck.
- Запустить все unit-тесты.
- Создать production-сборку.
- Запустить preview production-сборки.
- Вручную сыграть минимум три полных матча.
- Зафиксировать найденные балансные проблемы отдельным списком.
- Обновить README с командами запуска.

**Готово, когда**

- все автоматические проверки проходят;
- три матча завершились без блокирующей ошибки;
- команды запуска воспроизводимы на чистой установке;
- критерии P0 из GDD выполнены.

## 5. Готовый запрос coding-агенту для первой задачи

```text
Выполни только задачу P0-01 из docs/Implementation-Backlog-P0.md.

Создай минимальный браузерный проект на Vite, TypeScript strict и Phaser 4.1.0.
Подключи Vitest и npm-команды dev, typecheck, test, build и preview.
Пока не создавай игровые механики, сервер, сеть, UI-фреймворк или ассеты.

Перед изменениями прочитай:
- docs/GDD-v0.1.md
- docs/Technical-Design-v0.1.md
- docs/Implementation-Backlog-P0.md

После работы:
1. перечисли изменённые файлы;
2. покажи команды запуска;
3. запусти typecheck, тесты и production build;
4. сообщи все оставшиеся ошибки и риски.
```

После успешного завершения P0-01 агенту передаётся только следующая задача, а не весь P0 сразу.
